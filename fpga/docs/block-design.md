# Block Design Workflow

## 1. Choose the platform

- MicroBlaze bare metal: start from `create_microblaze_bd.tcl`.
- Zynq-7000 with the official FreeRTOS BSP: start from `create_zynq_bd.tcl`.
- If the board already has a validated BD, package only the custom AXI-Lite IP
  and use `add_axi_lite_to_bd.tcl`.

Set the real part and board part explicitly. A part number alone is not enough
to validate DDR, MIO, PS UART, reset polarity, or board pin assignments.

## 2. Create the design

MicroBlaze example:

```powershell
$env:TEMPLATE_PROJECT_DIR = "C:\work\platform"
$env:TEMPLATE_PROJECT_NAME = "platform"
$env:TEMPLATE_PART = "xc7k325tffg900-2"
$env:TEMPLATE_BD_NAME = "system"
vivado -mode batch -source fpga\tcl\create_microblaze_bd.tcl
```

Zynq example:

```powershell
$env:TEMPLATE_PROJECT_DIR = "C:\work\platform"
$env:TEMPLATE_PROJECT_NAME = "platform"
$env:TEMPLATE_PART = "xc7z020clg400-1"
$env:TEMPLATE_BOARD_PART = "<actual board part>"
$env:TEMPLATE_BD_NAME = "system"
vivado -mode batch -source fpga\tcl\create_zynq_bd.tcl
```

The scripts create external clock/reset or PS fixed IO/DDR ports, AXI GPIO,
AXI Timer, and the required processor infrastructure. They validate the BD and
generate a wrapper.

## 3. Package custom RTL

```powershell
vivado -mode batch -source fpga\tcl\package_axi_lite_ip.tcl
```

This packages `axi_lite_regs.v` as:

```text
user.org:user:axi_lite_regs:1.0
```

The generated `fpga/ip_repo` is build output and is ignored by Git. Re-run the
script after changing RTL; do not edit generated files by hand.

## 4. Add the custom IP

```powershell
$env:TEMPLATE_PROJECT = "C:\work\platform\platform.xpr"
$env:TEMPLATE_BD = "system"
$env:TEMPLATE_INSTANCE = "axi_lite_regs_0"
$env:TEMPLATE_OFFSET = "0x42000000"
vivado -mode batch -source fpga\tcl\add_axi_lite_to_bd.tcl
```

The script adds the AXI4-Lite slave, connects it to the selected processor
master, ties the demonstration status inputs low, assigns the requested address,
validates the BD, and prints the mapped offset.

## 5. Review the address and interrupt map

Example from the validated MicroBlaze flow:

| Device | Offset |
|---|---:|
| AXI GPIO | `0x40000000` |
| UARTLite | `0x40600000` |
| AXI INTC | `0x41200000` |
| AXI Timer | `0x41C00000` |
| AXI-Lite custom IP | `0x42000000` (when explicitly set) |

The exact values are generated by the BD. Never copy the table into firmware
without confirming the current `xparameters.h` and address report.

## 6. Validate before export

1. `validate_bd_design` passes.
2. No critical warnings remain for unconnected input pins.
3. Every AXI slave has a unique address and range.
4. Every interrupt source has a valid controller input.
5. Clock and reset domains are connected intentionally.
6. The wrapper is regenerated after the final BD change.
7. The XSA is exported only after completed Design Runs with a bitstream.

## 7. Common failures

- Missing part in the local Vivado installation.
- Board part has no matching PS7 preset or DDR configuration.
- Custom IP repository was not added to `ip_repo_paths`.
- Custom IP address collides with UART/GPIO/Timer/INTC.
- AXI-Lite read-only inputs left unconnected.
- Interrupt concat input count smaller than the number of interrupt sources.
- Exporting an XSA before the implementation and bitstream complete.
